# 0006. Generate API docs via CI; do not commit them

Status: Accepted

## Context

Doxygen output was previously committed directly to `docs/` in the
repository, generated by hand on a contributor's machine. A stray local
Doxygen run against the wrong working directory once produced tens of
thousands of unrelated files (from an unrelated Python virtual
environment) that got committed alongside the real output, growing the
repository by hundreds of megabytes before being noticed and cleaned up.
Independently of that incident, committed generated output is a general
liability: it drifts from source, bloats history, and creates merge
conflicts on files no one should be hand-editing.

## Decision

`docs/` (Doxygen HTML output) is git-ignored and never committed.
`.github/workflows/docs.yml` runs Doxygen on every push to `main` that
touches `adsblib.h`, `adsblib.c`, `README.md`, or `Doxyfile`, and deploys
the result directly to GitHub Pages via `actions/deploy-pages`. The
GitHub repository's Pages source must be set to "GitHub Actions" (not
"Deploy from a branch") for this to work — see the workflow file for
details.

## Consequences

- Generated docs can never again silently include unrelated content from
  a contributor's local machine — CI only ever sees a clean checkout of
  this repository.
- Contributors no longer need Doxygen installed locally to keep published
  docs up to date (though it's still useful for local preview — see root
  `README.md#documentation`).
- Docs publishing now depends on GitHub Actions/Pages being configured
  correctly (one-time manual repository setting); if that's ever
  misconfigured, the legacy GitHub-managed Jekyll "pages build and
  deployment" workflow can fire instead and fail, since it expects a
  `docs/` folder on `main` that no longer exists.
