Low-Cost ADS-B Out Architecture with Certification-Oriented Design and Integrated RF Monitoring

Abstract

This document proposes a low-cost architecture for an ADS-B Out (1090ES) system based on commercial off-the-shelf (COTS) components, explicitly designed with structural principles inspired by avionics certification standards. Unlike existing open-source ADS-B implementations focused primarily on reception or SDR-based transmission, this work explores a hardware-efficient, non-SDR transmitter architecture incorporating deterministic timing, built-in test (BIT), and real-time RF power monitoring. The goal is not immediate certification, but architectural compatibility with future certification processes under EASA/DO-260B and related avionics standards.

1. Introduction

Automatic Dependent Surveillance–Broadcast (ADS-B) is a core surveillance technology in modern air traffic management. Certified ADS-B Out transponders are typically expensive due to stringent requirements for reliability, environmental robustness, and certification overhead.

While ADS-B reception systems have seen extensive open-source development, transmission systems remain largely closed and certification-bound. This work explores whether a low-cost, non-SDR ADS-B Out system can be designed using a certification-aware architecture from the outset, reducing future redesign costs.

2. Problem Statement

Current ADS-B Out implementations suffer from:

  • High cost of certified avionics equipment
  • SDR-based experimental transmitters lacking regulatory compliance path
  • Lack of open architectures aligned with avionics certification processes
  • Absence of integrated RF health monitoring in low-cost designs

This work addresses the gap between experimental transmitters and certified avionics systems.

4. Key Design Principles

4.1 Non-SDR Deterministic RF Generation

The system avoids SDR complexity by using:

  • PLL-based carrier generation (ADF4351)
  • Digital RF switching for PPM modulation
  • Precomputed ADS-B frame generation in firmware

This ensures deterministic timing behavior suitable for certification-oriented design.

4.2 ADS-B Frame Generation

The system generates standard Mode S Extended Squitter (DF17):

  • 112-bit transmission frame
  • CRC-24 Mode S encoding
  • Position, velocity, and identification messages
  • Strict timing alignment with GNSS PPS signal

4.3 Built-In Test (BIT) Architecture

A hierarchical BIT system is implemented:

Power-On BIT

  • MCU memory integrity
  • GNSS validity check
  • PLL lock detection
  • RF path continuity test

Continuous BIT

  • RF power monitoring
  • GNSS signal integrity
  • supply voltage monitoring
  • thermal supervision

Failure conditions lead to transmission inhibition.

4.4 RF Monitoring Subsystem

A directional RF monitoring subsystem is included using a logarithmic detector (e.g., AD8318).

Functions:

  • Real-time transmitted power estimation
  • Detection of antenna disconnection
  • PA failure detection
  • Closed-loop power stability (optional)

The output is an analog voltage sampled by MCU ADC.

4.5 Safety-Oriented Transmission Control

Transmission is conditionally enabled only if:

  • GNSS position is valid
  • PLL is locked
  • RF power is within bounds
  • no critical system fault is active

Otherwise, transmission is inhibited.

5. Hardware Architecture

5.1 Microcontroller Unit (MCU)

Candidate devices:

  • STM32H5 series
  • STM32G4 series

Responsibilities:

  • ADS-B encoding
  • system supervision
  • BIT execution
  • RF control interface

5.2 GNSS Subsystem

Requirements:

  • Position, velocity, altitude
  • PPS output for timing synchronization
  • integrity reporting

Example devices:

  • u-blox M10 / F9 series

5.3 RF Synthesis

ADF4351 PLL synthesizer:

  • Frequency range: 35 MHz – 4.4 GHz
  • Output tuned to 1090 MHz
  • SPI-controlled configuration

Provides stable carrier generation for ADS-B transmission.

5.4 RF Modulation and Power Stage

  • Digital switching (PPM encoding)
  • RF power amplifier (20–33 dBm target range)
  • SAW filter centered at 1090 MHz

5.5 RF Monitoring

  • Logarithmic power detector (AD8318 or equivalent)
  • Analog output to MCU ADC
  • Optional closed-loop power regulation

6. Software Architecture

Layered design:

Application Layer │ ├── Health Monitoring (BIT) ├── Navigation Processing ├── ADS-B Encoding Engine │ ├── Hardware Drivers │ └── HAL (Hardware Abstraction Layer)

Key properties:

  • deterministic execution
  • strict separation of concerns
  • traceable functional requirements

7. Safety and Fault Management

The system defines explicit fault states:

  • GNSS invalid
  • PLL unlock
  • RF power out of bounds
  • memory corruption
  • thermal overload

Fault handling behavior:

  • immediate transmission inhibition
  • persistent fault logging
  • system status reporting

8. Certification-Oriented Design Considerations

Although not certified at initial stage, the architecture aligns with:

  • DO-260B (ADS-B Out specification)
  • DO-178C (software lifecycle considerations)
  • DO-160 (environmental testing)
  • DO-254 (if complex hardware is introduced)

Design practices include:

  • requirement traceability (REQ → TEST mapping)
  • configuration management
  • deterministic timing design
  • fault containment strategies

9. Expected Contributions

This work proposes:

  1. A non-SDR ADS-B Out architecture using COTS components
  2. Integration of RF monitoring into low-cost avionics-like design
  3. Built-In Test (BIT) framework inspired by certification standards
  4. A structured approach bridging experimental and certifiable avionics systems

10. Limitations

  • Not certified for operational aviation use
  • Requires extensive testing for regulatory compliance
  • RF emissions subject to national regulation
  • Certification requires additional environmental and safety validation

11. Conclusion

This architecture demonstrates that ADS-B Out systems can be designed using low-cost components while maintaining structural compatibility with avionics certification principles. The main contribution is not functional novelty of ADS-B transmission itself, but the integration of deterministic RF design, fault monitoring, and certification-oriented software architecture in a non-SDR, cost-constrained system.
